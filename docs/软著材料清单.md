- 建议排序（体现"接口 → 业务 → 数据"的完整链路）：

| 顺序 | 目录 | 理由 |
|---|---|---|
| 1 | `routes/api.php` | 一页看懂系统功能边界 |
| 2 | `app/Http/Controllers/Api/**` | 接口实现，命名即业务 |
| 3 | `app/Services/**` | 核心业务：认证、图鑑、交易、支付、担保 |
| 4 | `app/Models/**`、`app/Enums/**` | 数据模型与状态机 |
| 5 | `database/migrations/**` | 库表设计证据 |

生成与排版已固化为两个脚本（**在仓根目录执行**，只依赖 Python 3 标准库 + 本机 Edge/Chrome）：

```powershell
python docs/copyright/build_source_pdf.py    # 抽取 → 折行 → 排版 → 打印 PDF
python docs/copyright/verify_source_pdf.py   # 自动校对（页数/页码/页眉页脚/每页首末行）
```

产物（`docs/copyright/`，已在 `.gitignore` 中排除，可随时重建）：

| 文件 | 用途 |
|---|---|
| `GOAT-V1.0-源程序-前30页后30页.pdf` | **提交件**，60 页 |
| `source-all.txt` / `source-head-30p.txt` / `source-tail-30p.txt` | 抽取与分页中间产物，便于抽查 |
| `source-60p.html` | 排版源，改字体/字号后重打即可 |

排版要求（已写进脚本）：A4、单栏、等宽 8pt、每页固定 50 行、页眉"GOAT 潮玩交易平台 V1.0 源程序"、页脚连续页码；**前 30 页与后 30 页页码必须连续**（第 1–30 页、第 31–60 页）。

两个必须知道的坑：

1. **后 30 页不是"全文最后 1500 行"**，而是"全文末尾 30 页"——脚本先算总页数（当前约 311 页），从倒数第 30 页起截，页码重排为 31–60；直接切最后 1500 行会让中间少掉一大截。
2. **PHP 源码进 HTML 必须转义**：`<?php` 会被 HTML 解析成 bogus comment，一路吞到下一个 `>`，实测第 1 页凭空少 40 行。脚本用 `html.escape()` 兜住，渲染结果与源码一致。
