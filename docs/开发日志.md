## 2026-11-03（后端 T4/T5/T6 链路接线）

### 本轮交付（全部为服务端，三端前端仍为空目录）
- **T4 交易写侧**：卖家上架审核 → 开拍 → 出价（防狙击延时）→ 下单锁库 → 发货 → 确认收货，写侧全部接线
- **T5 支付/担保**：`PaymentChannel` 契约 + `SandboxChannel` 驱动（`hash_hmac('sha256', timestamp.body, secret)` + `hash_equals` + 时间戳容忍窗口防重放）；`Idempotency-Key` + DB 唯一约束双兜底；担保 `pending → frozen → settled`；费率在支付发起时快照，之后改费率不影响存量订单
- **T6 互动与社群**：收藏 / 购物车（加购**不锁库**，锁库只在下单事务）/ 关注 / 评价（一单一评、卖家只回一次、信用分由评价重算）/ 通知中心（`dedupe_key` 幂等）/ 图片帖机审管线（`pass / reject / review` 三态，异常转人工不 fail-open）/ 私信（会话归一化 + 拉取即已读）

### 工程口径
- 异常按域拆分：`TradeException`(422) / `CatalogException`(404/409/503) / `SocialException`(403/404/409/422)，前端按状态码分支而不是解析文案
- 可见性单点定义：帖子 feed 只认 `Post::scopeVisible()`（`approved` 且 `published_at` 非空），业务代码不手写 status 条件
- 私信本轮只做 HTTP 拉取；`messages.message_id` 单调递增，后续接 Reverb WS 不需要改表
- Windows 本机 PHP 8.3 NTS 装通：`ext-pcntl` / `ext-posix` 缺失用 `--ignore-platform-req` 绕过，**不写进** `composer.json` 的 `platform`（否则服务器侧会误以为缺扩展）

- **请求层单点收口**：`baseURL` + `Authorization` + 业务错误 Toast + 401 清缓存跳登录只在 `api/request.js` 实现；`Idempotency-Key` 由 API 层生成（下单 / 支付各一个），页面不关心。
- **沙箱支付闭环**：`SandboxGateway` 不直接改库，而是用 `SandboxChannel::signNotification()` 自签一条合法回调，再走 `PaymentService::applyNotification()` 正规链路——**演示路径 = 上线路径**，避免"演示能过、真回调挂掉"。测试覆盖越权付费 422、重复付费 422、通知去重。

### 工程口径
- **不引入 pinia**：登录态只是一个 `reactive` 单例 + 几个动作，多一个状态库对小包体积不划算；401 广播用 `uni.$emit('goat:unauthorized')` 解耦。
- **前端不硬编码中文枚举**：图鑑品类选项由后端 `meta.categories` 下发；订单状态与可执行动作集中在 `ORDER_STATUS`（页面只读 `action`）。
- **金额只做展示格式化**：`money()` 仅千分位 + 去尾零，不碰浮点；金额计算全部留在服务端 `Money`。
- **下单成功但支付失败不回滚**：弹窗引导去订单页补付，避免用户重复下单生成第二张单。

## 2026-11-03（实时推送 + 运营后台 + 采集桥接 + 软著 PDF）

### 本轮交付
- **Reverb 实时推送**：`MessageSent` / `NotificationCreated` / `BidPlaced` 三个事件 + `GET /realtime/config`（下发订阅地址）+ `POST /broadcasting/auth`（私有频道鉴权）。前端**不引 pusher-js / laravel-echo**：小程序没有全局 `WebSocket`，只用到 5 个协议帧，自研 ~180 行客户端（`app-mobile/src/realtime/client.js`）反而少一个升级风险点。
- **`admin-pc/` 运维后台**：Vue3 + Element Plus + vue-router + 原生 `fetch`（零 axios），5 个功能页——图鑑发布/编辑/归档、卖家入驻审核、商品审核、帖子审核（卡片流 + 机审标记）、采集触发与 job 查询；后端同步补 `GET /admin/sellers`（默认 `pending`，先到先审）与 `PostController::index` 的状态筛选。
- **采集桥接**：`InternalCollectorClient`（HMAC-SHA256 签名 + 超时 + 错误分类）→ `Admin\CollectorController`（仅 `role:admin`）→ 采集侧独立仓 `goat-collector`。未配置返回 503、上游失败返回 502，运营看到的是明确文案而不是 500。
- **`worker-pricing/` 只留说明**：采集实现不在本仓，写入 `worker-pricing/README.md` 讲清「为什么拆两个仓 + 契约 + 配置」，避免按目录找代码的人以为功能缺失。
- **`AdminUserSeeder`**：后台开箱可登录。口令来源 `GOAT_ADMIN_PASSWORD` → 随机生成并打印一次；已存在账号只补角色/状态，**不冲掉运营改过的密码**（显式配了密码才重置）。
- **软著源程序 PDF 流水线**：`docs/copyright/build_source_pdf.py` 抽取 158 个自有源文件 → 折行 → 排版（A4 / 8pt / 每页 50 行 / 页码连续 1–60）→ 前 30 页 + 后 30 页；`verify_source_pdf.py` 自动校对页数、页码、页眉页脚、每页首末行与字符量。

### 工程口径
- **WS 永不是单点故障**：未配置 key → 直接走 HTTP 拉取；订阅失败 → 静默重连；推送异常 → 只记 `Log::channel('security')`，业务事务已提交。
- **事件在事务外派发**：收信人不会查到「还不存在的消息」；**幂等回放不广播**——重试不是新事件，否则围观者看到同价出两次。
- **后台登录先校验角色再存 Token**：密码对但 `role !== admin` 时不落 Token，避免「拿到有效 Token 却处处 403」的困惑。
- **采集侧不重试**：抓取是长任务，重试属于采集侧队列职责，站点侧重试会把 1 个任务放大成 3 个。
- **PHP 源码进 HTML 必须转义**：`<?php` 会被 HTML 解析成 bogus comment 一路吞到下一个 `>`，实测第 1 页凭空少 40 行——这条坑写进了脚本注释。

### 口径（本轮踩过的坑）
- **`seller_id` ≠ `user_id`**：评价墙、关注、店铺主页三处的路径参数都是**卖家账号 id**，跳转一律用 `user_id`；卖家中心里误用 `seller_id` 会查到别人（或 404），已统一
- **`headline.available` ≠ 有站内成交**：只要任一外部源有点，它就为 `true`，但 `median/low/high` 只统计站内成交，前端要按 `median` 是否有值决定显示「¥xxx」还是「暂无站内成交」，否则会渲染出 `¥null`
- **公开索引已过滤在售**：`GET /listings` 只出 `active` 且有库存，前端不必再传 `status`
- **图片一律本地占位**：无图走 `<view class="placeholder">无图</view>`，不热链第三方图床
