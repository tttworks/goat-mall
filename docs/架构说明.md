## 1. 系统定位与边界

本软件是潮玩（可动玩具 / 手办）C2C 担保交易平台，包含服务端、C 端移动应用两部分，均在本仓：

| 组成 | 目录 | 技术栈 | 职责 |
|---|---|---|---|
| 服务端 | `backend/` | PHP 8.3 + Laravel 12、Sanctum、PostgreSQL 17 + TimescaleDB、Redis 7、Meilisearch | 认证、图鑑、卖家开店、商品、竞价、订单、支付担保、社群、私信、通知、后台审核 |
| C 端 | `app-mobile/` | uni-app（Vue3 + Vite），H5 / 微信小程序 / App 同源 | 图鑑浏览、商品详情、下单支付、订单管理、社群发帖、私信、收藏、通知 |
| PC 后台 | `admin-pc/` | Vue3 + Element Plus（**规划中**） | 图鑑审核发布、卖家审核、商品审核、帖子审核 |
| 行情采集 | 独立仓 `goat-collector` | Python 3.12 | 图鑑底库与行情采集，**不属于本软件** |

采集系统与本软件通过 PostgreSQL（共享库）、Redis（队列 / PubSub）、内部 HTTP（HMAC 鉴权）三类契约通信，双方不共享源码。

## 2. 总体架构

```
┌────────────────────────── 客户端 ──────────────────────────┐
│  uni-app(H5 / 小程序 / App)        Vue3 + Element Plus 后台  │
└───────────────┬────────────────────────────┬───────────────┘
                │ HTTPS / JSON               │
        ┌───────▼────────────────────────────▼───────┐
        │ Nginx（TLS、静态资源、/api 反向代理）        │
        └───────────────────┬───────────────────────┘
                            │
        ┌───────────────────▼───────────────────────┐
        │ Laravel 应用（Octane 常驻 worker，:8000）  │
        │ 路由 → 中间件 → 控制器 → 服务 → 模型/枚举  │
        └───┬───────────────┬───────────────┬───────┘
            │               │               │
     ┌──────▼─────┐  ┌──────▼─────┐  ┌──────▼──────┐
     │ PostgreSQL │  │   Redis    │  │ Meilisearch │
     │ +Timescale │  │ cache/队列  │  │ 图鑑检索     │
     └────────────┘  └────────────┘  └─────────────┘
```

- 应用层不直接拼接资源域名：数据库只存对象 key，URL 由 `App\Support\MediaUrl` 按 `MEDIA_BASE_URL` 统一拼接，换存储域名只改配置。
- 金额一律以「字符串小数」在接口层流转，运算集中在 `App\Support\Money`，禁止浮点参与计算。

## 3. 服务端分层

| 层 | 目录 | 约定 |
|---|---|---|
| 路由 | `routes/api.php` | 统一 `/api/v1` 前缀；`auth:sanctum` 分组；接口清单即功能清单 |
| 中间件 | `app/Http/Middleware` | `ForceJson`（响应恒为 JSON）、`EnsureSeller`（开店且审核通过）、`EnsureRole`（管理员） |
| 请求校验 | `app/Http/Requests` | 每个写接口一个 FormRequest，校验与控制器分离 |
| 控制器 | `app/Http/Controllers/Api` | 只做「取登录态 → 调服务 → 返回资源」，不含业务分支 |
| 服务 | `app/Services/**` | 业务规则唯一落点，按域分包：`Auth / Catalog / Seller / Trade / Payment / Social / Community / Moderation / Notify / Identity` |
| 资源 | `app/Http/Resources` | 出参裁剪，避免直接暴露模型字段 |
| 模型 / 枚举 | `app/Models`、`app/Enums` | 状态机集中在枚举（`transitions()` + `label()`），业务代码不手写状态字符串 |
| 异常 | `app/Exceptions` | 按域拆分：`AuthException` / `CatalogException` / `TradeException` / `SocialException` / `IllegalStateTransition`，统一映射为 4xx 并携带机器可读 `code` |

当前对外接口 **102 个**（GET 51 / POST 40 / PUT 3 / DELETE 7 / PATCH 1）。

## 5. 状态机

| 对象 | 状态流转 |
|---|---|
| 卖家 `SellerStatus` | `draft → pending → active`；`active ⇄ suspended` |
| 商品 `ListingStatus` | `draft → pending_review → active → reserved → sold`；`active ⇄ delisted`；`pending_review → rejected → draft` |
| 订单 `OrderStatus` | `pending_payment → paid → seller_shipped → buyer_confirmed → completed`；`pending_payment → cancelled`；`paid/seller_shipped/buyer_confirmed → refunding → refunded / closed` |
| 支付 `PaymentStatus` | `pending → paid → frozen → splitting → settled`；任一态可 `→ refunded / failed` |
| 竞价 `AuctionStatus` | `draft → scheduled → active → ended → settled`；`ended → failed`（流拍） |
| 帖子 `PostStatus` | `pending → approved / rejected`；`approved → withdrawn` |
| 图鑑 `FigureStatus` | `draft → published → archived`（发布仅管理员可触发） |

实现方式：枚举内 `transitions()` 白名单 + `StateTransitions` 特征校验，非法跃迁抛 `IllegalStateTransition`，与数据库 `CHECK` 约束形成双保险。

## 6. 关键数据流

### 6.1 担保交易（下单 → 支付 → 结算）

```
买家下单(Idempotency-Key) → orders 落库 + listings 置 reserved（同一事务）
   → 发起支付 → payments(pending) + 费率快照
   → 通道回调 → 验签(HMAC) → payments(paid→frozen) + orders(paid) + 通知双方
   → 卖家发货 → seller_shipped
   → 买家确认收货 → buyer_confirmed → completed
   → 资金解冻结算(payments: frozen→splitting→settled) + 触发评价入口
```

要点：
- 幂等：`Idempotency-Key` + 数据库唯一约束双兜底，重复请求返回同一笔，不产生第二单。
- 回调：签名校验使用 `hash_hmac('sha256', timestamp.body, secret)` 与 `hash_equals`，并校验时间戳容忍窗口防重放；签名或金额不符一律拒绝。
- 演示与生产同链路：沙箱渠道自签合法回调后仍走同一验签与状态机（`SandboxGateway`），不存在「演示专用旁路改库」。
- 费率在支付发起时快照，后续调整费率不影响存量订单。

### 6.2 UGC 发帖

```
发帖 → 机审通道(ModerationChannel) → pass: approved + published_at
                                    → reject: rejected（理由回传作者）
                                    → review: 转人工，不入 feed
feed 口径 = Post::scopeVisible()（approved 且 published_at 非空），全站单点定义
```

机审异常一律转人工，**不 fail-open**——通道故障不能让未审内容直接对外。

### 6.3 私信与通知

- 会话以「用户 ID 小者在前」归一化 + 唯一键，双方谁先发起都只有一条会话。
- 消息按 `message_id` 单调递增分页，打开会话即置已读并清零未读数；后续接 WebSocket 推送不需要改表结构。
- 通知以 `dedupe_key` 唯一约束去重，同一业务事件（如重复回调）只提醒一次。

## 7. 安全设计

| 关注点 | 措施 |
|---|---|
| 越权（IDOR） | 所有写接口的 `user_id` 取自 Token，路由参数只表示操作对象；订单/支付/收藏均校验归属 |
| 支付回调伪造 | HMAC-SHA256 签名 + 时间戳窗口 + 金额比对 + 幂等键 |
| 重复提交 | `Idempotency-Key` + DB 唯一约束；加购/收藏/关注/通知均幂等 |
| 状态跃迁 | 枚举白名单 + 数据库 `CHECK` 约束 |
| 敏感配置 | 全部走 `env()`，`.env` 与 `vendor` 不入仓；仓库只保留 `.env.example` 占位 |
| 内容风险 | 机审三态，异常转人工 |
| 传输与响应 | HTTPS；`ForceJson` 保证错误结构一致，不泄露堆栈 |

## 8. C 端应用架构

```
App.vue(onLaunch: bootstrapSession)
  └─ pages/            页面（图鑑列表、图鑑详情、商品详情、登录注册、社群、私信、
                        我的、订单、通知、收藏）
  └─ api/              接口层：request.js 统一 baseURL / Token / 错误 Toast / 401 跳转 / 幂等键
                       auth.js · catalog.js · trade.js · social.js
  └─ store/session.js  登录态单例（reactive），不引入额外状态库
  └─ utils/            storage.js（Token 缓存）· format.js（金额/时间/状态文案）· ui.js
  └─ styles/           设计变量（uni.scss）+ 跨页原子类（theme.scss）
```

设计要点：
- 请求层单点收口：页面不出现域名、Token、重复的错误提示代码。
- 金额只做展示格式化（千分位、去尾零），不参与计算。
- 状态文案与可执行动作集中在 `utils/format.js` 的订单状态表，页面按 `action` 渲染按钮，避免各页一套分支。
- 筛选项（如图鑑品类）由服务端 `meta` 下发，客户端不维护中文枚举副本。
