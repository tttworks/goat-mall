# 架构契约（GOAT Mall 双系统）

> **本文件是所有 agent（CodeBuddy 多模块并行）与两个仓库代码必须先读的唯一事实来源。**
> 任何一侧改接口/表结构，先改这里，再改代码。违者必然对不上。
> 版本：v1.0　生效：2026-11-03（对应讨论决策：图鑑入库优先、站点/采集双系统独立、双 LLM 按阶段切分、图鑑本地先跑）

---

## 1. 两个独立系统（物理 & 知识产权隔离）

| 系统 | 仓库 | 技术栈 | 部署 | 出网 IP | 职责 |
|---|---|---|---|---|---|
| **站点系统 GOAT-MALL** | `goat-mall`（站点仓库） | Laravel 12 + Octane(Swoole) + Reverb(WS) + Horizon；uni-app(Vue3) 四端；Vue3+ElementPlus PC 后台 | 应用进程（临时站反代 Octane:8000） | 仅业务出站（支付/对象存储/UGC 机审） | 交易、图鑑展示、社群、后台、对外 API |
| **采集系统 GOAT-COLLECTOR** | `goat-collector`（采集仓库） | Python 3.12（worker） | 独立进程 / 独立 systemd / 独立 venv | **日本归属 IP**（Mercari/eBay 行情必需；图鑑源 MFC/78dm/AmiAmi 不限地域） | 图鑑底库抓取整理、行情采集、数据清洗入库 |

**隔离原则（软著 + 安全）**
- 两仓互不 import 源码；仅通过 **PostgreSQL（共享库） + Redis（队列/PubSub） + 内部 HTTP（admin 触发）** 三类契约通信。
- Web 层**绝不直接持有**采集源的 token / 日本 IP / 爬虫凭据；这些只存在于 goat-collector 的运行时与 `/root/goat_secrets.env`。
- 软著可拆两件登记：「GOAT潮玩交易平台软件 V1.0」（站点）+「GOAT潮玩数据采集软件 V1.0」（采集）。

## 2. 共享数据层（PostgreSQL 17 + TimescaleDB，逻辑归属）

> 库名 `goat_mall`（已建），角色 `goat`。DB 只存 UFile **对象 key**，URL 由 API 层按配置拼。

### 2.1 图鑑 / 模玩主数据（采集系统写入，站点系统只读展示）
- `figures`（图鑑条目，Wiki 式，仅管理员发布）：figure_id(PK)、name、series、maker、scale、release_date、category、external_ids(jsonb: {mfc:<id>, amiaml:<id>, dmz78:<id>})、cover_key、gallery_keys(jsonb)、specs(jsonb)、created_at、updated_at
- `figure_sources`（数据源溯源）：source(PK part: mfc/78dm/amiAmi)、external_id、raw_payload(jsonb)、last_synced_at
- 索引：external_ids GIN；series / maker / category 普通索引（多维筛选）

### 2.2 商品 / 交易（站点系统主写）
- `listings`（在售商品）：listing_id、seller_id、figure_id(FK→figures)、title、condition_enum、price、currency、status、created_at
- `orders` / `order_items` / `payments`（收付通分账）、`auctions`（竞价，含 anti-snipe 字段）、`bids`

### 2.3 行情（采集系统写入，TimescaleDB hypertable）
- `price_points`（hypertable, time=observed_at）：point_id、source(enum: site/mercari_jp/ebay)、external_listing_id、figure_id(FK)、price、currency、condition、observed_at
- 连续聚合视图 `price_kline_1d`：per figure_id + source 的日 K（open/high/low/close/volume），供详情页 K 线
- **依赖关系**：行情的 `figure_id` 必须能锚定到 `figures`——这是「先做图鑑入库、行情后做」的根本理由。

## 3. Redis 队列契约（goat-collector ⇄ goat-mall）

| 队列 / Key | 生产方 | 消费方 | 用途 |
|---|---|---|---|
| `queue:crawl:figure` | admin API（站点） | collector worker | 触发图鑑条目抓取/增量同步 |
| `queue:crawl:price` | scheduler / admin | collector worker | 触发行情采集（Mercari/eBay/MFC） |
| `queue:ingest` | collector | collector ingest 阶段 | 清洗后数据落 PG 前的缓冲 |
| `channel:reindex` (PubSub) | collector | 站点（Laravel 指令 Reverb/Meili） | 图鑑/行情更新后通知前端刷新 |
| `meili:sync` | 站点或 collector | Meilisearch 同步 job | 索引更新 |

> 队列名**全局唯一、带前缀 `goat:`**，禁止两侧各起一套命名。

---

## 4. 内部 API 契约（站点 → 采集，仅 admin 触发用）

- `POST /internal/collector/crawl-figure` {figure_id | external_ids} → 202 + job_id
- `POST /internal/collector/crawl-price` {figure_id, source[]} → 202 + job_id
- `GET  /internal/collector/job/:job_id` → 状态（queued/running/done/failed + 进度）
- 鉴权：内部网段 + 共享 HMAC 头（密钥在 `/root/goat_secrets.env`，不进仓库）
- 反向上行（采集→站点）**不走 HTTP**，一律经 Redis 队列 + DB 写入，避免双向耦合。

---

## 5. 事件流（一条数据从爬取到展示）

```
[MFC/78dm/AmiAmi] --爬取--> collector.adapter --> queue:ingest
   --> collector.ingest(清洗/去重/规格归一) --> PG.figures / figure_sources
   --> PubSub channel:reindex --> 站点收到 --> Meili 重建索引 + Reverb 推前端
[行情] Mercari/eBay --爬取(日本IP)--> collector.pricing(price-engine.js 算法)
   --> PG.price_points(hypertable) --> 连续聚合 --> 详情页 K 线
```

## 6. 双 LLM 路由策略（DeepSeek + 智谱 GLM 5.3）

> 铁律：**禁止两个模型对同一份代码并行改写**（风格/契约分叉）。所有 agent 先读本契约 + 对应 OpenAPI/迁移文件再动手。

| 阶段 / 任务 | 主用模型 | 理由 |
|---|---|---|
| 批量脚手架、CRUD、迁移、样板、类型定义 | **DeepSeek**（V3/R1） | 快、便宜、代码生成强 |
| 中文业务语义、支付分账/竞价/费率、合规文案、注释与文档 | **智谱 GLM 5.3** | 中文推理与业务准确性更稳 |
| 跨模块接口一致性 review | GLM 5.3 做审校 | 抓契约偏离 |
| 算法（price-engine 移植、IQR/偏离带） | DeepSeek 生成 + GLM 复核数值语义 | 防统计误用 |

## 7. 安全边界（WAF 升级监控面，对应攻防 3.7a）

- 自研 WAF 安全面板（独立开源组件，作者 Aloysius Luo）监控维度：Octane worker 内存/重启、Reverb WS 连接数（目标 3-5k）、PgBouncer 池占用（头号隐藏瓶颈）、Redis 内存/pubsub、Meili task 积压、Horizon job 积压、采集器限流/IP 信誉。
- 业务层滥用规则：IDOR 越权、支付回调伪造、竞价狙击/竞态——WAF 与 Horizon 失败队列联动告警。
- 采集器出网受 WAF 监控，防被当攻击源；内部 API 走 HMAC + 内网。
- ⚠️ **WAF 代码不内联**：自研 WAF 面板为作者独立开源项目，GOAT 系统仅以外部安全层（nginx 配置 / API / 网络）集成，**绝不将其源码纳入本产品代码或软著提交材料**（避免权属混淆与软著退回）。

## 10. 软著申请注意事项（避免退回 → 否则无法上架）

- **框架版权**：uni-app 为 DCloud 开源框架，GOAT 仅在其上开发自有业务代码。软著登记的是 **GOAT 自有代码**，不含 uni-app / Laravel 等第三方框架源码。
- **框架边界**：提交软著材料（源程序 + 软件说明书）时，**只提交 GOAT 自有应用代码**，排除 `node_modules`、vendor、框架内部实现；混入第三方代码会增加退回风险。
- **双系统分别登记**：站点（goat-mall）→「GOAT潮玩交易平台软件 V1.0」；采集（goat-collector）→「GOAT潮玩数据采集软件 V1.0」。各自材料各自整理，权属边界清晰。
- **材料一致性**：软件说明书描述的功能 / 模块必须与提交的源程序对应；版本号格式「软件名称 V1.0」。
- **代码量**：确保自有代码量充足（通常 ≥ 3000 行或完整模块），避免被判定「非原创 / 量不足」退回。
- **WAF 不内联**（见 §7）：自研 WAF 安全面板为作者独立开源项目，系统仅以外部安全层集成，**绝不将其源码纳入本产品代码或软著提交材料**。
